v8 estende o DT-Kinase v7 injetando features cujo **sinal de treino provém de fonte externa** (supervisão, anotação curada, taxonomia). Features derivadas determinística ou auto-supervisionadamente do SMILES/sequência (GROVER, RDKit descriptors, MACCS, FCFP) foram **descartadas** porque não agregam informação além do que MoLFormer/ESM-2 já destilam.

## 3. Fusão arquitetural

**Princípio**: v8 é v7 + multi-modal. Toda injeção nova recebe as mesmas não-linearidades que v7 aplica às suas sequências (EmbeddingAdapter).

**Regra absoluta**: nunca mean pooling, nunca CLS. Sempre attention pooling com query aprendida.

- **Pré-attention injection** (participa do mapa 2D):
  - ChemBERTa per-token → `AttentionPool1D` → `Linear(384, ligand_dim=768)` + `LayerNorm` → **`EmbeddingAdapter`** (bottleneck=lig=512, dropout=0.35, `use_self_attn=False` pois é 1 token) → concat na dim sequencial ANTES do `lig_adapter` v7.
  - BioBERT per-token → `AttentionPool1D` → `Linear(768, protein_dim=320)` + `LayerNorm` → **`EmbeddingAdapter`** (bottleneck=prot=256) → concat ANTES do `prot_adapter` v7.
  - Adapter interno de v7 depois processa SEQUÊNCIA COMPLETA (token injetado + sequência backbone) → preserva tudo que v7 faz.
- **Post-pool concat** (após hierarchical attention pool do v7):
  - ADMET (171), ClassyFire (108), Pfam (~50), Taxonomy (~10) cada um com `LayerNorm` próprio → concat ao pooled vector → classifier ampliado `Linear(cnn_channels + extra_post, 1)`.
  - `LayerNorm` é essencial: ADMET endpoints span ordens de magnitude (logS ∈ [-7,0], Caco-2 perm ∈ [-6,-4]).

Query do `AttentionPool1D` treinada end-to-end.

**Total extra trainable**: ~800 K parâmetros (2× AttentionPool + 2× Linear proj + 2× EmbeddingAdapter + 4× LayerNorm + classifier ampliado).

## 10. Diagnóstico de colapso (histórico de falhas)

### Falha #1 (pré-fix `1bc3f72`): val_MCC=0 todas épocas

```
epoch 1..16 val: MCC=0.0000 thr=0.010 AUROC=0.5000
train_loss=0.0000 (stuck)
test: MCC=-0.2126 thr=0.752 AUROC=0.4831
```

Causa: AMP + cuDNN disabled → NaN gradients → `scaler.step` skip → modelo frozen no init. Fix em `1bc3f72`: `no_amp: true`, LayerNorm por feature, debug first batch.

### Falha #2 (pré-fix `1fe43e1`): overfit explosivo

Com fixes acima, training iniciou mas:
```
[debug batch 1] logits min=-2.76 max=2.19  loss=0.2092 grad_norm=9.27  y pos=66/128
epoch 1 train_loss=0.0036  val_MCC=0.1252  AUROC=0.6687
epoch 2-17 train_loss=0.0000  val_MCC ~0.07-0.13  (stuck)
test: MCC=0.1432  AUROC=0.6201
```

Causa: **shortcut memorization via identidade de composto**. ChemBERTa CLS + ADMET + ClassyFire concat é único por `chembl_id` → modelo decora train em 1 epoch. AUROC 0.67 vs v7 0.80 confirma features como ruído/shortcut, não sinal.

**Fixes em `1fe43e1`**:
- `nn.Dropout(p=0.5)` no fim de `chemberta_proj`, `biobert_proj`, e em todas post-pool features antes do concat
- Base LR 1e-3 → **1e-4** (overridável `V8_BASE_LR`)
- Optimizer param group novo para v8 modules: lr=1e-4 (sem `adapter_lr_mult ×5`), weight_decay ×5

### Falha #3 (aplicado fix `a602f5b`): overcorreção regularizatória

Depois dos fixes 1fe43e1 (dropout 0.5 + LR 1e-4 + weight_decay ×5), sinal v8 suprimido demais. User observou: v8 deve preservar v7 (bi-modal → multi-modal), incluindo aplicar EmbeddingAdapter às representações injetadas.

**Fixes em `a602f5b`**:
- **EmbeddingAdapter nas injeções**: ChemBERTa CLS e BioBERT CLS agora passam por instância própria de `EmbeddingAdapter` (mesma classe v7) antes do concat. Adapter interno regulariza via dropout próprio.
- **LR revertido 1e-3** (padrão v7). Overridable `V8_BASE_LR`.
- **Dropouts extras removidos** (0.5 em chemberta_proj/biobert_proj/post-pool) — redundante com adapter + layernorm.
- **Weight decay ×5 removido** → usa `weight_decay` padrão do config em todos os groups.
- `use_self_attn=False` para adapters de injeção (1 token → self-attn trivial).
